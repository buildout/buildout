Vendored code
=============

This directory contains third-party code that zc.buildout ships itself.

``pkg_resources``
-----------------

``pkg_resources/__init__.py`` is a copy of
https://github.com/pypa/setuptools/blob/v81.0.0/pkg_resources/__init__.py
— setuptools v81.0.0 is the last release that contained ``pkg_resources``;
it was removed in setuptools 82.0.0.

``zc.buildout`` (and many recipes and extensions) use the ``pkg_resources``
API as their data model for distributions, requirements and working sets,
so buildout ships its own copy and installs it as ``sys.modules
['pkg_resources']`` early in ``zc/buildout/__init__.py``.  See
https://github.com/buildout/buildout/issues/685 for the background.

Note that this copy is only importable *inside* a buildout run (or after
``import zc.buildout``).  Scripts generated by buildout for distributions
that use pkg_resources-style namespace packages still need a real
``pkg_resources`` (i.e. setuptools < 82) at script run time.

Deviations from upstream
~~~~~~~~~~~~~~~~~~~~~~~~

Each change is marked with a ``LOCAL CHANGE`` comment in the file:

1. A provenance and license note was added to the module docstring.
2. The ``sys.path`` extension with setuptools' private ``_vendor``
   directory and the ``sys.modules.pop('backports', None)`` workaround
   were removed: the dependencies they made importable are provided
   differently here (see 3. and 4.), and vendored code must not mutate
   the host process' ``sys.path``/``sys.modules``.
3. ``from jaraco.text import ...`` was replaced by an import from
   ``zc.buildout._vendor.jaraco_text`` (see below).
4. (No source change) ``platformdirs`` is imported unchanged; it is a
   regular install requirement of zc.buildout instead of being vendored,
   because it is pure Python and has no dependencies of its own.

Upstream's ``pkg_resources/tests/``, ``api_tests.txt`` and ``py.typed``
are not vendored: the first two are test-only, and the ``sys.modules``
alias is invisible to static type checkers anyway, so shipping type
information would not help.

``jaraco_text.py``
------------------

Contains the three helper functions (and their private helpers) that
``pkg_resources`` needs from ``jaraco.text``, copied unchanged from
``jaraco.text`` 4.0.0 as vendored by setuptools v81.0.0
(``setuptools/_vendor/jaraco/text/__init__.py``).  Vendoring all of
``jaraco.text`` — or depending on it — would drag in its dependency tree
(jaraco.functools, more-itertools, ...) for three small functions.

Re-sync procedure
-----------------

setuptools v81.0.0 is the final upstream release of ``pkg_resources``, so
re-syncs from upstream are not expected; future changes will be local
patches, which should be marked with ``LOCAL CHANGE`` comments and listed
above.  Should a re-sync ever be needed:

1. Download ``pkg_resources/__init__.py`` from the desired tag, e.g.
   https://raw.githubusercontent.com/pypa/setuptools/v81.0.0/pkg_resources/__init__.py
2. Re-apply the deviations listed above (diff against the current
   vendored copy to find them: look for ``LOCAL CHANGE``).
3. Update the version references in this file and in the module
   docstring.
